# 퍼즐 모음(puzzle-box) 설계

## 의도
개인 타임킬링용 퍼즐 모음. 지금 마방진 하나만 있는 저장소를 여러 퍼즐을 담는 곳으로 바꾼다. 들어가서 바로 고르고 바로 시작하는 것이 가장 중요하다. 휴대폰에서도 하므로 터치와 좁은 화면을 지원한다.

## 목표
- 첫 화면은 퍼즐 고르기. 이번에 넣을 퍼즐은 마방진(기존), 기사의 여행, 별 배치(뮤도쿠식 영역 퍼즐) 세 가지.
- 다음 퍼즐은 폴더 하나만 추가하면 붙는 구조.
- 저장소, Pages 주소, 로컬 폴더 이름을 `puzzle-box`로 변경.

## 하지 않을 것
- 퍼즐마다 "만드는 법" 설명 페이지(마방진 설명 페이지는 그대로 둔다).
- 빌드 도구, 프레임워크, 외부 라이브러리.
- 계정, 서버, 랭킹, 레벨 진행 저장.

## 실패로 볼 것
- 기존 마방진 게임이나 설명 페이지가 깨지거나 동작이 달라짐.
- 별 배치가 뮤도쿠를 베낀 것처럼 보임(이름, 고양이 그림, 화면 모양, 레벨). 장르 규칙만 쓴다.
- 풀 수 없거나 정답이 여러 개인 별 배치 문제가 나옴.

## 제약
- 정적 파일만 사용(HTML/CSS/JS). GitHub Pages가 `main`의 루트를 그대로 서비스한다.
- 기존 마방진의 색과 버튼 스타일(라이트/다크 토큰)을 공통으로 쓴다.

## 접근 방식 (검토한 것)
- **A. 퍼즐마다 폴더 + 공통 CSS — 선택.** 빌드 없이 지금 방식 유지. 퍼즐끼리 서로 영향 없음. 퍼즐 추가는 폴더 추가로 끝.
- B. 한 페이지에서 탭 전환: 전환은 매끄럽지만 파일이 커지고 코드가 얽힘. 마방진 설명 페이지도 다시 짜야 해서 제외.
- C. React/Vite 등 도구 도입: 개인용 퍼즐 몇 개에 과함. 빌드 단계와 배포가 복잡해져서 제외.

## 구조
```
index.html            퍼즐 고르기 화면 (카드 3개: 이름, 한 줄 규칙, 링크)
common.css            공통 토큰(:root 라이트/다크), body, 버튼, .seg, .controls, .status, .msg
magic-square/
  index.html          기존 index.html 이동
  guide.html          기존 guide.html 이동
  magic.js            기존 magic.js 이동
knights-tour/
  index.html
  knight.js           규칙, 풀이기, 힌트 (DOM 없이 Node에서도 돌아가게)
star-battle/
  index.html
  stars.js            생성기, 풀이기, 검증 (DOM 없이 Node에서도 돌아가게)
README.md             퍼즐 모음 기준으로 다시 작성
```
- 각 퍼즐 페이지 상단에 `← 퍼즐 목록` 링크(`../`).
- 마방진은 공통 CSS로 바꿔도 화면이 지금과 같아야 한다. 공통으로 뺀 것 외의 스타일은 페이지 안에 남긴다.

## 기사의 여행
체스 나이트(L자 이동)로 판의 모든 칸을 정확히 한 번씩 밟는다. 시작 칸으로 돌아올 필요는 없다(열린 여행).
- 크기: 5×5, 6×6, 7×7, 8×8.
- 시작: 아무 칸이나 눌러 시작. "무작위 시작" 버튼도 둔다. 5×5와 7×7은 일부 칸에서만 여행이 가능하므로, 불가능한 칸을 누르면 시작하지 않고 안내한다(풀이기로 판정).
- 진행: 갈 수 있는 칸을 누르면 이동. 밟은 칸에는 순서 번호가 표시된다.
- 도움 표시(켜기/끄기, 난이도 역할): 켜면 다음에 갈 수 있는 칸을 강조한다. 끄면 강조가 없다.
- 막힘: 갈 곳이 없는데 칸이 남으면 "막혔어요"라고 알리고 되돌리기를 권한다.
- 버튼: 되돌리기, 다시 시작, 힌트, 새 게임. 힌트는 지금 위치에서 끝까지 갈 수 있는 다음 칸 하나를 알려준다(Warnsdorff 순서의 백트래킹 풀이기. 이미 끝까지 못 가는 상태면 "여기서는 완주할 수 없어요, 되돌려 보세요"라고 알림).
- 상태 표시: 밟은 칸 수/전체, 시간, 힌트 사용 수. 다 밟으면 성공 메시지.

## 별 배치 (뮤도쿠식 영역 퍼즐, 장르명 Star Battle)
n×n 판이 n개의 색깔 영역으로 나뉜다. 별을 n개 놓는다.
- 규칙: 가로줄마다 1개, 세로줄마다 1개, 색깔 영역마다 1개. 별끼리는 대각선을 포함해 이웃 8칸에 붙을 수 없다.
- 크기(난이도 역할): 5×5 ~ 9×9.
- 조작: 칸을 누를 때마다 빈칸 → X → ★ → 빈칸으로 바뀐다. 휴대폰과 PC에서 같다.
- 규칙 위반: 같은 줄, 같은 영역, 이웃에 별이 겹치면 그 별들을 빨간색으로 표시한다. 하트나 벌점은 없다(편하게 하는 용도).
- 버튼: 되돌리기, 지우기, 힌트, 정답 보기, 새 게임. 힌트는 틀린 별이 있으면 그 칸을 짚어주고, 없으면 정답 별 하나를 놓아준다.
- 상태 표시: 놓은 별 수/n, 시간, 힌트 사용 수. 규칙을 다 만족하면 성공 메시지(정답 예시와 같은지가 아니라 규칙 만족 여부로 판정. 문제는 정답이 하나뿐이므로 결과는 같다).
- 생성: ① 규칙을 만족하는 별 배치를 무작위로 만든다 → ② 각 별에서 영역을 무작위로 키워 판을 n개 영역으로 나눈다 → ③ 풀이기로 정답이 정확히 하나인지 확인하고, 아니면 영역을 조정하거나 다시 만든다. 새 게임은 9×9에서도 휴대폰 기준 1초 안에 나와야 한다.
- 모양: 장르 이름 "별 배치"와 ★ 기호, 영역은 연한 파스텔 색 n개(라이트/다크 모두 구분 가능). 고양이, 뮤도쿠 이름, 화면 배치는 쓰지 않는다.

## 이름 바꾸기
1. 코드 작업이 끝나고 푸시한 뒤 `gh repo rename puzzle-box`를 실행한다(로컬 `origin` 주소도 함께 바뀐다). `gh`는 `C:\Program Files\GitHub CLI\gh.exe`.
2. Pages 새 주소 `https://dndnpdpr-stack.github.io/puzzle-box/`가 열리는지 확인한다. 예전 `magic-square/` 주소는 404가 된다.
3. README의 링크는 새 주소 기준으로 쓴다.
4. 로컬 폴더 `D:\myproject\magic-square` → `D:\myproject\puzzle-box`는 사용자가 세션을 닫은 뒤 직접 바꾼다.

## 확인
- 생성기와 풀이기(knight.js, stars.js)는 Node로 테스트한다: 생성된 별 배치 문제가 규칙을 만족하고 정답이 하나뿐인지, 기사의 여행 풀이기가 각 크기에서 완주 경로를 찾는지.
- 세 페이지를 브라우저에서 열어 PC 폭과 휴대폰 폭에서 한 판씩 해 본다.

## 구현하는 쪽에 맡기는 것
