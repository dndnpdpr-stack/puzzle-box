# 스도쿠 설계

## 의도
퍼즐 모음(`puzzle-box`)에 네 번째 퍼즐로 9×9 스도쿠를 넣는다. 개인 타임킬링용이고 휴대폰에서도 한다. 사용자는 어려운 문제도 붙잡고 풀 수 있게 **메모(후보 숫자) 기능**과 **쉬움·보통·어려움** 난이도를 원했다. 앞서 별 배치에서 정한 방향을 그대로 따른다: 힌트는 정답을 채워 주지 않고 근거를 알려주며, 정답과 다른 입력은 바로 빨간색으로 보여준다.

## 목표
- `sudoku/` 폴더 하나와 첫 화면 카드 하나로 붙는다(퍼즐 추가 규칙 그대로).
- 문제는 매번 새로 만들고 정답은 항상 하나.
- 난이도는 실제로 푸는 데 필요한 기법으로 나눈다(아래 "난이도").
- 메모: 칸마다 후보 숫자 1~9를 적고 지울 수 있다.
- 힌트는 사람이 쓰는 기법으로 다음 한 수와 이유를 보여준다.

## 하지 않을 것
- 9×9 외의 크기, 변형 규칙(대각선, 킬러 등).
- 외부 문제 모음, 빌드 도구, 라이브러리, 서버, 기록 저장.
- 마방진 설명 페이지 같은 "만드는 법" 페이지.

## 실패로 볼 것
- 정답이 둘 이상이거나 풀 수 없는 문제가 나옴.
- 난이도 표시와 실제 필요한 기법이 맞지 않음(예: 쉬움인데 쌍 기법이 필요).
- 힌트가 정답을 그냥 채워 주거나, 틀린 근거를 보여줌.
- 휴대폰(360~390px)에서 판이나 숫자판이 잘리거나 가로 스크롤이 생김.
- 새 게임이 휴대폰에서 눈에 띄게 오래 걸림(목표: 어려움도 PC 기준 평균 0.3초, 최악 1초 이내).
- 기존 세 퍼즐 동작이 바뀜.

## 제약
- 정적 HTML/CSS/JS, `common.css`의 토큰·버튼·`.controls`/`.status`/`.msg`/`.back` 사용.
- 로직은 `sudoku/sudoku.js`에 DOM 없이 두고 Node 내장 테스트(`node --test`, `tests/sudoku.test.js`)로 검증. 내보내기 형식은 다른 로직 파일과 같음(`module.exports` 또는 전역 `Sudoku`).
- 화면 문구는 한국어.

## 접근 방식 (검토한 것)
- **A. 풀이 기법으로 난이도 판정 — 선택(사용자가 고름).** 완성 판을 무작위로 만들고 정답이 하나로 유지되는 동안 숫자를 지운다. 지운 판을 기법 풀이기로 풀어 필요한 가장 어려운 기법으로 난이도를 정한다. 같은 기법 엔진을 힌트에 쓴다. 코드가 가장 많고 어려움 생성에 재시도가 필요할 수 있다.
- B. 주어진 숫자 개수로 판정: 간단하지만 체감 난이도와 어긋나고, 힌트용 근거 엔진은 어차피 따로 필요해 제외.
- C. 미리 만든 문제 모음: 외부 데이터 금지 원칙과 맞지 않고 반복돼서 제외.

## 기법과 난이도
기법 풀이기는 후보 목록(칸마다 들어갈 수 있는 숫자)을 유지하며 아래 기법을 쉬운 것부터 차례로 적용한다.

| 단계 | 기법 | 화면 이름(힌트 문구용) |
|---|---|---|
| 1 | 하나뿐인 자리(Hidden single): 줄·열·박스에서 어떤 숫자가 들어갈 칸이 하나뿐 | 이 숫자가 들어갈 곳이 여기뿐 |
| 1 | 하나뿐인 숫자(Naked single): 칸에 들어갈 숫자가 하나뿐 | 이 칸에 들어갈 숫자가 이것뿐 |
| 2 | 박스-줄 갇힘(Pointing / Box-line): 박스 안 숫자 후보가 한 줄에만 있음, 또는 그 반대 | 갇힌 숫자 |
| 2 | 쌍·세 쌍(Naked/Hidden pair, triple) | 두(세) 칸이 숫자를 나눠 가짐 |
| 3 | X-Wing, Swordfish, XY-Wing | 사각형으로 묶인 숫자 등 |

- **쉬움**: 1단계만으로 풀림. 주어진 숫자 36~45개.
- **보통**: 1·2단계로 풀리고 2단계가 한 번 이상 필요. 주어진 숫자 28~35개 근처(개수는 결과일 뿐 기준은 기법).
- **어려움**: 3단계가 한 번 이상 필요하고, 1~3단계로 끝까지 풀림(추측·백트래킹이 필요한 문제는 내지 않음).
- 생성: 완성 판 → 칸을 무작위 순서(점대칭 쌍으로)로 지우며 정답 유일성 유지 → 기법 풀이기로 등급 판정 → 원하는 등급이 아니면 다시 만든다. 쉬움은 지우는 개수를 일찍 멈춰 1단계만 필요한 판을 얻는다. 시간 목표를 넘기면 지우는 방식(멈춤 시점, 재시도 횟수)을 조정한다.

## 화면과 조작
```
← 퍼즐 목록
스도쿠
가로줄·세로줄·3×3 박스마다 1~9를 한 번씩 채우세요.
[난이도: 쉬움|보통|어려움]  [되돌리기][지우기][힌트][정답 보기][새 게임]
남은 칸 41 · 시간 03:12 · 힌트 2
┌───────────── 9×9 판 (박스 경계 굵게) ─────────────┐
└──────────────────────────────────────────────────┘
[1][2][3][4][5][6][7][8][9]   [메모 ✎][지우개]
```
- 칸을 누르면 선택된다. 선택한 칸의 줄·열·박스는 옅게, 같은 숫자가 있는 칸은 진하게 강조한다.
- 숫자판(또는 키보드 1~9)으로 입력. 방향키로 선택 이동, Backspace/Delete/0으로 지우기. 주어진 숫자 칸은 바뀌지 않는다.
- **메모 모드**: '메모' 버튼을 켜면 숫자판이 선택 칸의 후보를 켜고 끈다. 후보는 칸 안에 3×3 작은 숫자로 표시. 확정 숫자를 넣으면 같은 줄·열·박스의 메모에서 그 숫자를 자동으로 지운다. 확정 숫자가 있는 칸에는 메모를 쓰지 않는다.
- **틀린 숫자**: 정답과 다른 확정 숫자는 바로 빨간색. 같은 줄·열·박스에 같은 숫자가 겹쳐도 둘 다 빨간색.
- 숫자판 버튼 아래에 그 숫자가 몇 개 남았는지 표시하고, 9개를 다 쓰면 흐리게.
- 되돌리기는 숫자 입력·지우기·메모 변경(자동 지움 포함)을 한 단위로 되돌린다.
- **지우기 버튼**: 사용자가 넣은 숫자와 메모를 모두 지운다(되돌리기 한 번으로 복구).
- **힌트**: 순서대로 (1) 틀린 확정 숫자가 있으면 그 칸을 짚는다 (2) 없으면 기법 엔진이 지금 판에서 다음 한 수를 찾아, 근거 칸을 강조하고 이유를 문구로 보여준다. 기법이 1단계(칸이 정해짐)면 그 칸과 숫자를 짚기만 하고 대신 넣지 않는다. 2·3단계(후보 제외)면 해당 칸들의 메모에서 그 후보를 지우고(메모가 비어 있는 칸은 먼저 그 칸의 후보 전체를 채운다) 이유를 보여준다.
- **힌트의 후보 계산(구현자 판단으로 정함)**: 사용자의 메모는 틀릴 수 있어 쓰지 않는다. 게임 상태에 "힌트가 이미 적용한 후보 제외 목록"을 따로 두고, 힌트 후보 = 확정 숫자로 계산한 후보 − 이 목록. 그래서 힌트를 다시 누르면 같은 제외를 반복하지 않고 다음 추론으로 넘어간다. 이 목록 변경도 되돌리기 한 단위에 포함되어 되돌리기·지우기 버튼으로 함께 되돌아간다. 숫자 하나를 지우개로 지울 때는 목록을 그대로 둔다: 힌트 제외는 확정 숫자가 모두 정답일 때만 만들어지므로 항상 참이라 남아 있어도 틀린 근거가 되지 않는다(구현 중 판정). 엔진 함수는 `(판, 제외 목록)`을 받아 다음 한 수를 돌려준다.
- **힌트 횟수(구현자 판단으로 정함)**: 다른 퍼즐과 같이 힌트 버튼을 누를 때마다 1회로 센다(틀린 칸 짚기 포함).
- **정답 보기**: 판을 정답으로 채우고 잠근다. 성공·정답 보기 뒤에는 입력·되돌리기·힌트·지우기가 동작하지 않고 타이머가 멈춘다.
- 성공 메시지: "🎉 완성! {난이도} 스도쿠를 mm:ss만에 풀었습니다 (힌트 k회)."
- 판 크기는 화면 폭에 맞추고, 화면 회전·창 크기 변경 때 다시 맞춘다. 320px에서도 넘치지 않는다.

## 확인
- Node 테스트: 생성한 문제가 정답 하나뿐인지, 정답이 규칙을 만족하는지, 등급별로 필요한 기법이 기준과 맞는지(쉬움은 1단계만, 보통은 2단계 필요·3단계 불필요, 어려움은 3단계 필요), 각 기법이 손으로 만든 예제에서 맞게 동작하는지, 힌트만 반복해서 끝까지 풀리고 정답과 어긋나는 제외를 하지 않는지, 생성 시간.
- 브라우저(헤드리스 Chrome, PC 1280·휴대폰 390/320, 라이트·다크): 숫자 입력·메모·자동 지움·되돌리기·틀린 숫자 빨간색·힌트·완성 잠금·크기 변경.
- 첫 화면 카드에서 열리고 `← 퍼즐 목록`으로 돌아오는지. README에 스도쿠 단락과 파일 구조 추가.

## 구현하는 쪽에 맡기는 것
- 화면 세부 배치, 강조 색, 칸 크기 계산.
- 생성기의 지우기 순서·재시도 세부(시간 목표와 등급 기준만 지키면 됨).
- 3단계 기법 중 무엇을 실제로 넣을지(X-Wing은 필수, 나머지는 어려움 생성 비율과 시간에 따라).
