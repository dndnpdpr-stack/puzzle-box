# 스도쿠 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 퍼즐 모음에 메모·기법 기반 난이도(쉬움/보통/어려움)·근거를 보여주는 힌트를 갖춘 9×9 스도쿠를 추가한다.

**Architecture:** `sudoku/sudoku.js`(DOM 없음)에 판 표현, 유일해 검사, 기법 엔진, 등급 판정, 생성기, 힌트를 둔다. `sudoku/index.html`은 그 API만 써서 화면·메모·되돌리기를 다룬다. 기법 엔진은 후보 비트마스크 배열 위에서 동작해 손으로 만든 후보 상태로 기법을 따로 테스트할 수 있다.

**Tech Stack:** HTML/CSS/바닐라 JS, Node 24 `node --test`(외부 패키지 없음), 브라우저 확인은 scratchpad의 CDP 드라이버(`drive.js`, 헤드리스 Chrome).

**Spec:** `docs/superpowers/specs/2026-11-26-sudoku-design.md`

## 표현 (모든 Task 공통)

- 판 `grid: number[81]`, 칸 번호 `i = r*9 + c`, 0은 빈칸. 박스 번호 `b = floor(r/3)*3 + floor(c/3)`.
- 후보 `masks: number[81]`, 숫자 d(1~9)는 비트 `1 << d`. 숫자가 있는 칸은 0.
- 힌트가 적용한 제외 `elim: number[81]`(같은 비트 형식). 힌트 후보 = 확정 숫자로 계산한 후보 & ~elim.

## Review Focus

1. **주어진 숫자 칸에 입력·메모·지우기** → 아무 일도 없어야 한다 (Task 5 브라우저 테스트 `given-locked`).
2. **숫자를 넣어 메모가 자동으로 지워진 뒤 되돌리기** → 숫자와 지워진 메모가 함께 복구 (Task 5 `undo-restores-memos`).
3. **판이 다 찼지만 틀린 숫자가 있을 때** → 성공 아님, 힌트는 틀린 칸부터 짚음 (Task 4 `hint-wrong-first`, Task 5 `full-but-wrong`).
4. **같은 힌트를 연속으로 누름** → 같은 제외를 반복하지 않고 다음 추론으로 (Task 4 `hints-alone-solve`).
5. **이미 숫자가 있는 칸에서 메모 모드 입력** → 메모를 쓰지 않음, 숫자가 있는 칸에 다른 숫자를 넣으면 교체 (Task 5 `memo-on-filled`).

### Task 2: 기법 엔진과 등급 판정

**Files:** Modify `sudoku/sudoku.js`, `tests/sudoku.test.js`

**Interfaces:**
- Consumes: Task 1 전부.
- Produces:
  - `findStep(grid, masks) -> Step | null` 쉬운 기법부터 첫 번째로 찾은 한 수. 제외형 기법은 실제로 지울 후보가 있을 때만 결과를 낸다.
  - `Step = { tech, level, place?: { cell, digit }, eliminate?: { cell, digit }[], focus: number[], unit?: { type, index }, digits?: number[] }`
  - 기법 이름과 단계(찾는 순서도 이 표 순서):

    | tech | level | 내용 |
    |---|---|---|
    | `hidden-single` | 1 | 한 단위에서 숫자 d가 들어갈 칸이 하나 → `place` |
    | `naked-single` | 1 | 칸 후보가 하나 → `place` |
    | `pointing` | 2 | 박스 안 d 후보가 한 줄(행/열)에만 → 그 줄의 박스 밖 d 제외 |
    | `box-line` | 2 | 행/열 안 d 후보가 한 박스에만 → 그 박스의 그 줄 밖 d 제외 |
    | `naked-pair` / `naked-triple` | 2 | 단위 안 칸 k개 후보 합집합 크기 k → 단위의 다른 칸에서 제외 |
    | `hidden-pair` / `hidden-triple` | 2 | 단위 안 숫자 k개가 같은 칸 k개에만 → 그 칸들의 다른 후보 제외 |
    | `x-wing` / `swordfish` | 3 | d가 행 k개에서 열 k개에만(또는 반대) → 그 열(행)의 다른 칸에서 d 제외 |
    | `xy-wing` | 3 | 축 칸 {x,y}, 날개 {x,z}·{y,z}(축과 각각 같은 단위) → 두 날개를 모두 보는 칸에서 z 제외 |

  - `grade(puzzle) -> { level: 1|2|3|null, steps: Step[] }` 빈 elim에서 `findStep`을 반복 적용(place는 숫자 넣기, eliminate는 마스크에서 제거). 끝까지 풀리면 사용한 최고 level, 막히면 `null`.

- [ ] **Step 1: 실패하는 테스트**. 기법 예제는 `grid`를 0으로 채우고 `masks`를 손으로 만든다(규칙 일관성 불필요). 도우미 `maskOf(...digits)`, `allMasks = Array(81).fill(0b1111111110)`.
  - `hidden-single`: 0행에서 d=5 비트를 칸 3만 남기고 모두 끔 → `{ tech:'hidden-single', place:{cell:3,digit:5} }`. 같은 masks에 어떤 칸도 후보 1개가 아니도록 둠.
  - `naked-single`: `allMasks`에서 칸 40만 `maskOf(7)` → `place {cell:40, digit:7}`(hidden-single이 먼저 걸리지 않게 다른 칸 후보는 전부 1~9).
  - `pointing`: 박스 0에서 d=3 후보를 칸 0·1에만(0행) → `eliminate`가 0행의 칸 3~8 중 d=3 후보 있는 칸 전부, `tech:'pointing'`.
  - `naked-pair`: 0행 칸 0·1 = `maskOf(1,2)` → 0행 다른 칸에서 1·2 제외. 같은 박스 0 안에서도 제외되는지는 단위별 결과이므로 `unit.type === 'row' || 'box'` 중 첫 번째만 검사.
  - `x-wing`: d=4 후보를 1행·5행에서 각각 열 2·7에만, 다른 행의 열 2·7에는 d=4 후보 있음 → `tech:'x-wing'`, `eliminate`가 정확히 (다른 행, 열 2·7)의 d=4.
  - `xy-wing`: 축 칸 0 `{1,2}`, 날개 칸 2 `{1,3}`(같은 행), 칸 18 `{2,3}`(같은 열); 칸 20은 날개 둘 다 보는 칸(박스 0·행 2… 칸 20은 칸 2와 박스, 칸 18과 행) 후보에 3 포함 → `eliminate` 에 `{cell:20, digit:3}` 포함. 앞 단계 기법이 걸리지 않도록 나머지 칸은 `allMasks`.
  - `grade levels`: Task 1 `randomFull`에서 숫자 하나만 지운 판 → `level 1`. 실제 판 등급 테스트는 Task 3에서.
  - `steps are sound`: 무작위 완성 판에서 45칸을 지운(유일해인 경우만) 판 20개에 대해 `grade`의 모든 place는 정답 숫자, 모든 eliminate는 정답 숫자를 지우지 않음.

### Task 5: 스도쿠 페이지

**Files:** Create `sudoku/index.html`

**Interfaces:** Consumes `Sudoku.generate`, `Sudoku.hint`, `Sudoku.peers`, `Sudoku.candidates`; `common.css`.

화면(위에서부터): `← 퍼즐 목록` · `h1` "스도쿠" · `.sub` "가로줄·세로줄·3×3 박스마다 1~9를 한 번씩 채우세요." · `.controls`[난이도 `.seg` 쉬움/보통/어려움(기본 보통) · 되돌리기 · 지우기 · 힌트 · 정답 보기 · `.primary` 새 게임] · `.status`[남은 칸 · 시간 · 힌트 사용] · 판 · 숫자판(1~9 버튼, 각 버튼 아래 남은 개수 작게, 9개 다 쓰면 `disabled`) + 메모 토글(`.on`) + 지우개 · `.msg` · `.help`.

상태: `grid`(현재 판), `given: boolean[81]`, `memo: number[81]`(비트), `elim: number[81]`, `history: { grid, memo, elim }[]`(바꾸기 전 스냅샷, 한 동작 = 한 항목), `selected`, `memoMode`, `hintCount`, `done`, 타이머.

동작:
- 칸(`<button>`)은 CSS grid 9열. 칸 크기 `max(30, min(56, floor((min(innerWidth,720) - 32) / 9)))`, 측정 전에 `--cs`를 30px로 줄였다가 잰다(별 배치와 같은 이유), `resize` 때 다시. 박스 경계 3px `--ink`, 칸 사이 1px `--line`.
- 선택 칸: `--sel` 배경, 같은 줄·열·박스 옅은 배경, 같은 숫자 칸 진한 강조. 주어진 숫자는 `--ink` 굵게, 입력 숫자는 `--accent`, 틀린 숫자(정답과 다름 또는 peers에 같은 숫자)는 `--bad`.
- 입력: 숫자판 또는 키보드 1~9. 일반 모드는 숫자 넣기(같은 숫자를 다시 누르면 지움), 넣으면 peers의 memo에서 그 비트 제거. 메모 모드는 빈칸의 memo 비트 토글(숫자 있는 칸은 무시). 지우개·Backspace·Delete·0은 숫자, 없으면 메모 지우기. 방향키 선택 이동. 주어진 칸은 모든 입력 무시. `N` 키로 메모 모드 토글.
- 메모 표시: 빈칸 안 3×3 작은 숫자(`font-size: calc(var(--cs) * 0.26)`).
- 지우기 버튼: 주어지지 않은 칸의 숫자·memo·elim 모두 초기화(한 history 항목).
- 힌트(`hintCount++` 매번): `Sudoku.hint(grid, solution, elim)`.
  - `wrong`: 그 칸 깜빡임 + "이 칸의 숫자가 틀렸어요."
  - place(level 1): 그 칸 초록 테두리 + 근거 칸(`focus`) 옅은 초록, 숫자는 넣지 않음. 문구: hidden-single "{단위}에서 {d}이(가) 들어갈 수 있는 칸은 초록 칸뿐이에요." / naked-single "초록 칸에 들어갈 수 있는 숫자는 {d}뿐이에요."
